# 移动指令、截图记录与后退校准

## 人工指令立即加入训练（最新行为）

在 train/drive 模式下按 W/A/D/B，完成短按和后图读取后，程序将**该动作所依据的前图**以人工动作标签追加到 navigation_dataset/labels.csv，同时更新 navigation_model.json，并在当前会话重新加载分类样本，无需重启。所有人工方向指令都会被视为示范，包括原先分类不明确的画面；自动动作不进入训练标签，避免自我强化错误。

终端会显示“人工示范已加入训练并生效”，会话中另存 `<id>_learning.json`。样本仅追加、已有样本编号和特征不变时自动迁移 Q 策略指纹，保留原 Q 值；人工示范并不代表奖励，Q 更新次数仍只由 train 模式中的评分更新。新增的 backward 样本不足 5 张时不会自动放开后退分类，仍可继续人工示范。

按键若发生在截图期间，使用该请求随后实际执行时的前图，并保存该图供核对。失败或取消的动作不会作为成功示范加入。新增一张图片不保证所有相似画面立刻被可靠识别，原有歧义和样本数量门槛仍保留。若按错键，需要在 labels.csv 中人工纠正标签后重新建立策略；同时运行多个采集/训练进程可能冲突，请只使用一个写入进程。

此行为替代下文“日志不会自动成为样本”的旧描述，仅限明确的人工 W/A/D/B 命令。默认按压仍为 500 ms。

## 截图与指令如何对应

每次实际移动在 `navigation_rl_logs/<会话>/` 中保存：

| 文件 | 内容 |
| --- | --- |
| `<id>_before.jpg` | 发出指令所依据的截图，960 像素宽，与模型输入一致，不带程序文字叠加 |
| `<id>_after.jpg` | 指令释放后获取的截图；失败时可能不存在 |
| `<id>.json` | 动作、按钮、像素坐标、来源、目标时长、时间戳、完成或错误状态 |
| `review.csv` | 逐动作索引，预留 `corrected_action` 和 `notes` 供人工校准 |
| `transitions.jsonl` | 会话事件、动作、奖励和退出记录 |

日志中的 `prepared/dispatching` 只表示准备/开始调用；`completed` 表示控制调用返回且后图已保存，不能证明小车实际走到了哪里。错误记录保留前图和原因。保存前图或初始日志失败时不会发动作。

人工复核 CSV 中的前后图，在 `corrected_action` 填应采取的动作（forward/up_left/up_right/backward/stop），在 notes 中记录偏差。不要覆盖原 action，以便保留模型实际做了什么。此 CSV 是校准记录，不会自动写回标签集或重训。

策略选择 stop 时不发送触摸，保存对应前图并在 transitions.jsonl 中记录 `policy_stop`。因识别门槛不通过而保持暂停不算移动指令。

## 截图间隔与按压时间

现在 `--interval-ms` 默认等于 `--pulse-ms`，`--settle` 默认 0，`--stable-frames` 默认 1，去掉了原来固定 0.5 秒等待及每个动作后的三帧等待。需要更保守的连续确认时可设置 `--stable-frames 3`。

```powershell
.\.venv\Scripts\python.exe .\rl_navigation.py --mode drive --pulse-ms 150 --interval-ms 150 --settle 0
```

采用串行闭环：前图 → 分析并保存 → 按压并释放 → 后图。截图开始时间不足目标间隔时才补等待，超时时立即继续，不排队补发动作，不用旧截图追赶目标频率。空闲观察也按目标间隔尽量读取。

ADB 截图传输、图像保存、推理和触控启动均有耗时，因此**设置相同只能表示目标相同，不能保证 100 ms 按压对应每 100 ms 一张截图**。不会为追赶截图速度擅自延长移动时间。

JSON/CSV 记录 `actual_capture_interval_ms`（配对前后截图请求开始的时间差）和 `command_elapsed_ms`（包含 ADB 开销的调用总耗时），后者并非测得的手机实际触摸时长。JSON 中另存 before/after 截图起止单调时钟值和 wall_time，可计算连续步骤之间的间隔；单调时钟值不能当作日期显示。
