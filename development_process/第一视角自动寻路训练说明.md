# 第一视角自动寻路训练方案

当前手机已经连接，实时画面显示的是小车前方低视角：能看到深色道路、白色车道线、黄色减速带和右侧绿色边界。这个视角可以用于训练道路跟踪，但不能把手机 App 的完整截图直接拿去训练，必须先用人工驾驶动作标注画面。

## 训练流程

```text
人工驾驶小车并采集画面
       ↓
按动作标注当前画面
       ↓
检查各类样本是否均衡
       ↓
训练可解释基线模型
       ↓
实时推理（只显示，不控制）
       ↓
验证稳定后，再接入短时控制
```

首版使用最近中心分类器，目的是验证数据是否有区分度，不是最终的自动驾驶模型。它会把画面缩小、提取 Lab 颜色和边缘特征，比较当前画面与每种人工标注动作的平均特征距离。

## 1. 采集人工驾驶样本

保持 scrcpy 窗口和小车 App 打开，先把小车架空或放在安全的短赛道上。使用手机或 scrcpy 手动驾驶，在采集窗口按键标记当前画面：

```powershell
.\.venv\Scripts\python.exe .\collect_navigation_data.py --serial 10AG1Z064A004P3
```

按键含义：

| 按键 | 标签 | 采集场景 |
| --- | --- | --- |
| `W` | `forward` | 直道、正常前进 |
| `A` | `up_left` | 左前方转弯 |
| `D` | `up_right` | 右前方转弯 |
| `S` | `stop` | 前方阻塞、需要停车或已停车 |
| `X` | `obstacle` | 动态障碍进入前方安全走廊 |
| `N` | `uncertain` | 看不清、画面异常或无法判断 |
| `Q` | 退出 | 停止采集，不发送触控 |

采集窗口只读取画面和保存图片，**不会调用方向控制代码，也不会发送 ADB 触摸命令**。方向操作仍由你通过手机或 scrcpy 完成。

每种标签先采集 30～100 张，覆盖直道、左弯、右弯、减速带、不同距离和不同光照。不要连续复制同一画面；每次动作前后都应记录几帧。`stop`、`obstacle` 和 `uncertain` 不能只采集一两张，否则模型会倾向于一直前进。

数据保存在 `navigation_dataset`：图片和 `labels.csv`。视频区被 App 按钮覆盖的画面也会被记录，后续应检查是否需要裁剪或屏蔽固定 UI。

## 2. 训练模型

样本达到要求后运行：

```powershell
.\.venv\Scripts\python.exe .\train_navigation_model.py
```

输出 `navigation_model.json`，同时打印各类样本数量。缺少有效图片、少于 12 张或只有一类标签时会停止，不生成模型。

## 3. 只读实时推理

```powershell
.\.venv\Scripts\python.exe .\run_navigation_inference.py --serial 10AG1Z064A004P3
```

窗口会显示预测标签和距离值，并明确显示 `NO CONTROL`。按 Q 退出。先观察模型在直道、左弯、右弯和障碍物前是否稳定，再决定是否更换特征或增加数据。

## 4. 当前不能直接自动驾驶的原因

- 数据还没有采集，模型没有训练依据。
- 手机画面包含固定 App 控件，需要先确认它们不会干扰特征。
- 这只是动作分类器，没有道路中心、车身偏移、速度和刹车距离估计。
- 最近中心分类器没有置信度校准，距离大时应当判为不确定并停车。
- 手机截图和小车视频有延迟，预测动作不能直接等同于当前真实位置。

只有当只读推理在多段赛道上稳定，并确认松开按钮会停车，才考虑将预测标签映射为 `up`、`up_left` 和 `up_right` 的短时脉冲。自动控制必须保留步数上限、画面超时停车、人工急停和物理边界。
