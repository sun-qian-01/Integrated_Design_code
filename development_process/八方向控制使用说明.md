# 手机小车 App 八方向控制

## 功能与实现方式

`phone_direction_control.py` 使用现有 ADB，对手机 App 的八个方向位置发送定时触摸：上、下、左、右、左上、右上、左下、右下。图形界面使用 Python 自带的 Tkinter；画面读取使用持续 scrcpy 视频流，需要先安装 `requirements-vision.txt` 中的依赖。详见[持续视频流取帧说明](持续视频流取帧说明.md)。

每次操作是在同一坐标执行 `input touchscreen swipe x y x y 持续毫秒数`，模拟原地按住后释放，并在结束或报错时尝试补发 `motionevent UP`。本机手机已确认支持这两个输入命令。

这不是向小车直接发送运动协议，也不是向电脑发送方向键。方向名称表示屏幕按钮所在位置，实际对应前进、后退、转向还是其他动作，需要在小车 App 中确认。

## 1. 启动图形控制面板

保持手机在截图中的横屏控制页面，scrcpy 可继续显示实时画面。在项目目录打开 PowerShell：

```powershell
python .\phone_direction_control.py
```

程序自动查找 WinGet 目录或 PATH 中的 ADB，并自动选择唯一已授权设备。也可以明确指定本次手机：

```powershell
python .\phone_direction_control.py --serial 10AG1Z064A004P3
```

若未找到 ADB，用 `--adb '实际路径\adb.exe'` 指定即可。

## 2. 先校准八个坐标

程序启动后默认勾选“校准模式”，并读取一张手机截图，不发送任何触摸事件。

1. 保持“校准模式”开启，点击面板上的一个方向按钮，例如“左上”。
2. 在下方截图中点击该方向对应的实际触控位置。
3. 对其他方向重复操作，观察彩色标记是否落在目标区域内。
4. 点击“保存坐标”，在脚本旁生成 `phone_direction_points.json`，下次自动加载。
5. 手机界面变化后，点击“刷新手机截图（只读）”重新校准。

截图是静态校准预览，实时视频仍看 scrcpy。面板中的校准点击只修改本地坐标，不会点击手机。

默认点位根据提供的截图估算，参考区域去掉了 Windows 标题栏。首次接口查询时，手机横屏坐标范围为 2800×1260。脚本通过视频流获取画面，通过手机逻辑显示尺寸保留原始触控坐标，使用归一化坐标映射，因此移动或缩放 scrcpy 窗口不会影响坐标。

**四个斜向点是上下左右之间的预估触控区域，不是已验证有效的按钮。** 截图不能证明 App 支持八方向；如果 App 只接受四方向，点击交界处可能无响应或被识别成单一方向，需校准并实测。若斜向要求两个独立手指同时触控，这个单点方案不适用，不能用先后两次点击代替同时触摸。

## 3. 执行短时方向控制

先架起车轮，确保可以从手机或电源开关停止小车。校准完成后：

1. 将按压时长设为 `200` 毫秒，初次测试也可从 `100` 毫秒开始。
2. 取消勾选“校准模式”。
3. 单击一个方向按钮，程序发送一次指定时长的按压并释放。
4. 观察小车响应及松开后是否停止，再测试其他方向。

时长范围为 50～2000 毫秒。面板采用“单击一次、执行一次短按”的方式，不是“按住电脑按钮就持续行驶”。一次操作执行期间禁用其他操作，防止排队积累运动指令。

每次运动前会从持续视频流读取新帧确认横屏，但不会自动识别当前是不是小车 App。操作前必须让手机停留在正确界面；切换 App、出现弹窗或布局改变都可能导致点错位置。

ADB 触控和视频传输存在额外延迟，设定时长只是触摸持续时间，并非从点击电脑按钮到小车停止的总耗时。持续视频流减少了重复截图开销，实际控制频率仍需实机测量。

## 4. 从命令行或其他 Python 程序调用

只读检查所有坐标，不发送触控：

```powershell
python .\phone_direction_control.py --dry-run
```

发送一次“上”方向 200 毫秒按压：

```powershell
python .\phone_direction_control.py --direction up --duration-ms 200
```

发送一次“右上”方向 150 毫秒按压：

```powershell
python .\phone_direction_control.py --direction up_right --duration-ms 150
```

可用方向：`up`、`down`、`left`、`right`、`up_left`、`up_right`、`down_left`、`down_right`。命令行指定方向会直接发送触控，不受图形界面校准开关控制；先校准、保存后再使用。

供后续程序集成的调用示例（运行即发送一次触控）：

```python
from phone_direction_control import (
    CONFIG_PATH, PhoneController, find_adb, load_points, pixel_point,
)

controller = PhoneController(find_adb(), serial='10AG1Z064A004P3')
controller.connect()
points = load_points(CONFIG_PATH)
_, width, height = controller.screenshot()
target = pixel_point(points['up'], width, height)
controller.press(target, duration_ms=200)
```

## 5. 释放与异常处理的边界

正常执行时，定时 swipe 自带释放；程序额外尝试发送 UP。如果断开 USB、ADB 异常、进程被强行结束或 App 保持运动状态，无法保证释放事件送达，也不能保证小车停止。关闭 scrcpy 不等于停车。

图形界面会等待当前操作完成再允许关闭；不要依靠关闭程序作为急停。发现小车持续运动时，使用手机的已验证停止操作或设备电源开关。

## 6. 验证方式

模拟测试不连接手机、不发送运动指令：

```powershell
python -m unittest -v test_phone_direction_control.py
```

测试覆盖八方向坐标、横屏限制、截图尺寸读取、定时按压与释放顺序、错误时释放尝试，以及无效时长不发送触控。`--dry-run` 额外验证实际设备连接和截图读取；以上检查不能替代实车的八方向响应与停车验证。

本次只读检查成功连接手机并读取截图，但检查时手机已为竖屏，因此程序拒绝继续输出控制点位。请先进入横屏小车控制页，再执行 `--dry-run` 或刷新校准截图。本次未发送任何运动指令。

## 7. 后续实车反馈与视觉导航

用户后续反馈八方向已通过初步测试：左上/右上为向左前/右前转弯，左下/右下为相应倒车转向；单独左/右只转车轮，不产生前后运动。斜向动作已获得初步实车反馈，但松开后的停车和车轮回正行为仍需确认。

视觉观察和局部导航程序见 `vision_navigation.py`，操作方法见 `视觉识别与局部自动导航.md`。该程序沿用现有坐标文件，前转弯使用左上/右上，不使用单独左/右代替行驶动作。
