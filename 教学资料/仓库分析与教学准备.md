# 仓库分析与教学准备

分析日期：2026-10-10。仓库：<https://github.com/sun-qian-01/Integrated_Design_code>，本次克隆版本 `a8cef74`（initial commit）。代码已直接放在 `/home/linjingtao/integrated-design`，没有额外仓库目录嵌套。

## 1. 结论

现有仓库是一个**借助安卓手机 App 控制小车的教学原型**，覆盖设备接入、局部颜色分割、人工采样、简单分类和人工奖励 Q-learning。它可以作为课程起点，但尚不是双摄像头自主竞速系统。

课程安排已按更正更新为：**前六天理论学习与小规模模块实践，第七天正式比赛**。建议主线为：**设备与数据链路 → 局部道路感知 → 全局定位 → 路径跟踪与反馈控制 → 学习方法与评价 → 双视角协同与系统验证**。学习方法作为对比实验，不能把“模型训练完成”当作“能自主完赛”。具体六天大纲见 [三个PPT六个上午教学大纲](三个PPT六个上午教学大纲.md)。

## 2. 代码实际实现

| 文件与入口 | 实际功能 | 教学用途与边界 |
| --- | --- | --- |
| `phone_direction_control.py`：`PhoneController`、`pixel_point` | ADB 查找设备、读取横屏 PNG 截图、归一化按钮坐标映射、定时触摸与释放；提供 Tkinter 校准面板 | 接口封装、坐标、异常处理；没有直接控制电机或读取编码器 |
| `vision_navigation.py`：`capture` | 调用手机截图，解码后缩放至宽 960 像素，记录截图开始/结束时间 | 讲清图像来源；不是直接读取车载摄像头视频流，也不是读取 scrcpy 窗口 |
| `vision_navigation.py`：`calibrate`、`analyze` | 道路 ROI、App 遮挡掩膜、Lab 地面颜色距离、形态学开运算、与近处中间区域连通的地面、左中右通行比例 | 可解释视觉基线；“像地面的像素”不等于已验证可通行道路 |
| `vision_navigation.py`：`propose`、`DecisionGate`、`monitor` | 前进/左右前转/停止建议；三帧一致；画面年龄、界面锚点、疑似冻结检查；有限步数与连续转向限制 | 状态机、闭环、时序和保护；当前不是中心线跟踪器，也不是全局路径规划 |
| `collect_navigation_data.py` | 用按键标注最近截图，保存 JPG 和 CSV | 数据采集与标签设计；按 W/A/D 等是标注，不会发送驾驶命令 |
| `train_navigation_model.py`：`features`、`train` | 图像缩至 32×18，拼接 Lab 三通道和 Canny 边缘，共 2304 维；对每类求均值 | 最近类中心分类器；没有神经网络、反向传播或训练/验证集划分 |
| `run_navigation_inference.py` | 计算到各类中心的欧氏距离，显示最近类别 | 仅观察，不控制小车；没有独立的可靠性评估流程 |
| `rl_navigation.py`：`Demonstrations`、`QPolicy` | 最近示例索引与上一次动作构成离散状态；示例先验、样本覆盖与类别差距限制；表格 Q-learning，人工给奖励 | 展示状态/动作/奖励与探索；不是深度强化学习，也没有自动圈速奖励 |
| 两个 `test_*.py` | 控制接口 mock 测试、合成图像与决策门限测试 | 回归测试范例；测试通过不证明真实视频、实车停车或完赛能力 |
| `vision_profile.json`、`phone_direction_points.json` | 某台手机和某个场景的标定参数 | 作为格式示例；更换设备、画面布局或场地需要重新标定 |
| `navigation_dataset/`、`navigation_model.json`、日志目录 | 少量演示图片、类中心模型、历史决策与数据审计 | 数据偏差、复现和失败分析素材 |

实际链路：

```text
车载摄像头 → 小车原有无线链路 → 手机 App 中的视频
                                      ↓ ADB screencap
电脑：解码图像 → 感知 → 决策 → ADB 模拟 App 触摸
                                      ↓
                              手机 App → 小车运动
```

scrcpy 用于人工投屏和交互，当前 Python 感知程序并未消费其视频流。全局摄像头接入及其后续模块均需要新增。

### 数据集

直接统计 `navigation_dataset/labels.csv`：64 个样本，对应图片均存在。

| 标签 | 数量 |
| --- | ---: |
| 左前 `up_left` | 29 |
| 直行 `forward` | 22 |
| 右前 `up_right` | 10 |
| 停车 `stop` | 2 |
| 障碍 `obstacle` | 1 |
| 不确定 `uncertain` | 0 |

CSV 中记录的截图耗时：最小 0.7826 秒、中位数 1.2760 秒、最大 1.6094 秒。这是**历史样本中的截图调用耗时**，不是本机当前实测，也不包含车载视频此前经历的全部无线传输和 App 缓冲延迟。不能据此直接宣称整套系统的帧率或控制频率。

仓库已有 `navigation_rl_logs/dataset_audit.json` 的留一图像最近邻检查中，对角线合计 32/64，约 50%；停车 2 张和障碍 1 张均未被正确识别。此结果不是类中心模型的独立测试成绩，相邻帧还可能造成泄漏，适合作为“如何审视模型评价”的反例。

### 本地检查结果

- 已阅读全部 6 个功能 Python 文件、2 个测试文件及相关说明文档，核对模型、配置和数据表。
- 使用本机 `python3` 运行已有测试：控制模块 6 项测试通过。
- 视觉测试因缺少 `cv2` 未能导入；本机同时缺少 NumPy 和 Tkinter。没有为本次教学分析安装运行环境。
- 未连接手机、小车或全局摄像头，没有执行任何实车动作；不能宣称完成硬件联调。
- `requirements-vision.txt` 锁定了 OpenCV 与 NumPy 版本；开课前需要在学生实际操作系统与 Python 版本上验证可安装性和 API 兼容性。本次没有验证这两个锁定版本。

## 4. 需要讲清的实现限制

1. **截图延迟影响闭环。** 当前每次截图涉及 ADB、PNG 传输和解码；三帧一致、动作执行和等待新画面又增加反应时间。提速前先测端到端延迟，不能只缩短 `pulse_ms`。
2. **截图时间不等于摄像头曝光时间。** `Frame.started` 是开始获取手机截图的时刻；App 可能已经在显示旧视频。现有时间检查不能独立证明车载画面足够新。
3. **动作是离散按钮短按。** `up_left` 是左前动作；仓库文档记录单独 `left/right` 仅转车轮。实车需复测。当前接口没有已验证的连续转角和速度设定能力。
4. **停止存在执行边界。** 自动程序中的 `stop` 多数表现为暂停后续动作；已发出的短按仍可能执行到结束。释放触摸不构成独立硬件急停，断连后是否停车须实测。
5. **地面颜色基线可能不适合复杂赛道。** 路缘、虚线、阴影和装饰物会改变颜色统计，后续要加入中心线、车道边界或其他道路特征。
6. **学习特征包含整张手机画面。** 采集与分类没有统一裁掉 App UI；模型可能依赖界面、固定背景或位置巧合，需要统一 ROI 并补充独立数据。
7. **标签语义混合。** `forward/up_left/up_right/stop` 是动作，`obstacle/uncertain` 是场景或可靠性状态。教学时应解释二者关系，后续可分别输出动作建议和风险状态。
8. **相似度不是概率。** 欧氏距离与类别间隔只能表示当前特征空间里的相似关系，不能直接当作识别正确概率或真实碰撞风险。
9. **保护条件会误报。** 静止车前的正常画面也可能长时间不变；固定 App 锚点只能检查有限的界面变化。应通过日志讲解误报与漏报。
10. **配置尚未声明完成实车验证。** 当前 `controls_verified` 和 `release_stops_verified` 均为 `false`；不能为了启动演示直接改为 `true`。

## 5. 面向竞速需要补充什么

以下为建议模块名，**当前仓库没有实现这些文件**。

| 优先级 | 建议模块 | 最小功能 | 教学安排 |
| --- | --- | --- | --- |
| 课前 | 环境与设备包 | 统一可安装依赖、设备说明、连接排障、按钮标定与停车验证 | 教师准备，第一天使用 |
| 课前 | `replay_source.py` | 读取两路录制视频、附带帧号/时间信息，允许离线调试 | 六天共用 |
| 高 | `global_camera.py` | USB/网络全局摄像头读取，输出最新帧和接收时间 | 第三天 |
| 高 | `global_localization.py` | 地面平面标定、识别小车位置和朝向、定位有效性输出 | 第三天 |
| 高 | `track_map.json` | 按规定方向排列的路点、边界、起终点、检查点 | 第三天 |
| 高 | `local_lane.py` | 车载 ROI 的道路中心偏差、近处异常、有效性 | 第二至四天 |
| 高 | `path_follower.py` | 选前视路点、计算偏差、映射为离散动作 | 第四天 |
| 高 | `race_controller.py` | 双视角信息仲裁、状态机、动作到期与故障处理 | 第六天 |
| 高 | `race_metrics.py` | 检查点顺序、方向性过线、圈数、完赛与干预统计 | 第六天讲解，第七天应用 |
| 中 | `evaluate_navigation.py` | 按采集批次划分数据、混淆矩阵与独立视频评价 | 第五天 |
| 中 | 视频/控制链路优化 | 根据实测选择更低延迟接入，统一适配接口 | 课前验证，第六天讲解 |
| 可选 | 搜索、学习升级 | 分岔赛道的 A*，轻量分类器，仿真 Q-learning | 提高任务 |

前六天应分别验收接口、感知、定位、控制、学习评价与协同模块，第七天再综合竞赛。课堂能否完成这些小规模练习，关键在课前是否打通设备接入，并提供离线素材、定位骨架、简化仿真和集成参考程序。没有额外项目时间时，需以教师已联通系统为基础替换学生模块；不要把未知硬件接口探索全部留给学生。

## 6. 开课前助教准备清单

- 确认每天上午实际课时、下午是否有上机、小组人数、设备与赛道预约方式。
- 确认全局摄像头固定方式、覆盖范围、允许贴定位标记与否；测量遮挡及小车在图像中的大小。
- 确认单车计时还是多车同场、合法赛道方向、越界/碰撞/接管判定、发车与计圈规则。
- 使用一套真实教学设备完成“短直道—左弯—右弯—完整低速一圈”，记录失败和链路耗时。
- 测量按钮短按响应、松手后行为、最小有效脉冲、转弯半径与停止滞后；没有速度接口时预先明确如何比较节奏参数。
- 准备同一场景的两路录制视频、标定点、路点、典型失败帧及可回放日志，设备不足时仍可完成实验。
- 给学生提供设备适配、视频读取和日志骨架，让学生重点实现感知、跟踪、策略和验证。
- 准备固定测试路段及重复试跑表；统一版本、参数与比赛前冻结时间。
