### 安装和验证

在 Windows 项目目录中运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r .\requirements-vision.txt
.\.venv\Scripts\python.exe -B -m unittest discover -v
```

设备操作还需要 scrcpy 和已授权的 Android USB 调试连接。先进行方向校准、采集本地示范数据，再运行训练或展示；具体命令见对应说明。自动测试使用模拟控制，不向实车发送动作。

### 代码与本地实验文件

为了保持现有导入和命令兼容，Python 入口、测试及使用说明保留在根目录，教学材料放在 `教学资料/`。以下内容保留在本机，由 `.gitignore` 排除：

- `navigation_dataset/`：训练截图、动作标签及赛道像素标注。
- `navigation_logs/`、`navigation_rl_logs/`：运行日志、动作前后图片和离线识别预览。
- `navigation*_model.json`、`navigation*_policy.json`：训练模型与学习到的策略。

新克隆的仓库不包含这些实验文件。赛道模型需先标注并训练；临时使用原策略时，可通过 `--no-track-guard` 禁用边界约束，但仍需要本地动作示范和触控坐标。代码与说明可复现训练流程，不代表附带了已训练模型。


## 一、项目定位

以一款自带摄像头、可由手机端操控的玩具小车为载体，引导学生从人工遥控逐步过渡到程序控制、图像识别、路径搜索和自主导航。

核心任务是：**小车根据摄像头看到的环境，识别障碍与可通行方向，选择行动，并根据新的观察修正行为，最终到达指定目标。**

课程以“感知—决策—行动—反馈”的闭环理解具身智能，而不只是演示一个图像识别模型。初期不追求任意环境下的通用自动驾驶，优先在受控场地完成可解释、可复现的实验。

## 二、接手时优先确认的条件

当前已知：小车自带摄像头、支持手机操控；项目希望加入障碍物识别、寻找道路、搜索与具身智能教学。

| 待确认事项 | 具体问题 | 对项目的影响 |
| --- | --- | --- |
| 设备与交接资料 | 小车型号、说明书、供应商、现有代码与历史问题有哪些？ | 判断现有基础及复用范围 |
| 视频接口 | 能否脱离原手机 App 获取视频流？延迟与清晰度如何？ | 决定视觉处理能否落地 |
| 控制接口 | 是否有 SDK 或开放协议？能否编程控制前进、转向、停止？ | 决定自主控制可行性 |
| 通信方式 | 使用 Wi-Fi、蓝牙或其他方式？视频和控制能否同时工作？ | 决定系统连接方案 |
| 安全机制 | 断连后是否自动停止？如何人工接管？ | 决定实车测试边界 |
| 运动反馈 | 是否有编码器、IMU？速度与转向是否可调？ | 决定定位和路径执行方式 |
| 教学条件 | 学生基础、课时、分组人数、设备数量、预算是多少？ | 决定课程规模和难度 |

**首个关卡是验证设备可二次开发。“手机可以控制”不等于“自编程序可以控制”，也不代表视频流能够直接读取。**

## 三、教学目标与教改思路

### 3.1 学习目标

1. 理解图像采集、预处理、障碍判断与可通行区域提取的基本流程。
2. 学会将简化场地表示为栅格或路口节点图，明确搜索的状态、目标与代价。
3. 实现和比较基础搜索算法，理解规划路径与实际运动之间的差异。
4. 通过反馈修正小车动作，理解感知不确定性、动作误差和环境变化。
5. 能够设计实验、记录数据、分析失败原因并展示可复现的成果。

### 3.2 教改设计

- **项目驱动**：围绕“安全到达目标”组织知识学习，而非分散讲解算法。
- **跨知识融合**：连接图像识别、搜索算法、控制与工程实践。
- **分层任务**：基础组完成循路与停车，提高组完成地图搜索，拓展组探索未知环境。
- **过程评价**：兼顾功能效果、算法理解、实验分析、协作和个人贡献。
- **效果证据**：结合课前课后同类任务、阶段作品和学生反馈评估学习变化，不将演示成功直接等同于教改有效。

## 四、任务分层与项目边界

### 4.1 第一层：最小可行闭环

在室内平整、光照相对稳定的受控场地，使用明显道路边界或标线、静态障碍物及可识别终点标记，完成：

1. 获取并显示摄像头画面。
2. 使用程序控制运动，保留人工停止或接管能力。
3. 判断道路方向及前方是否存在障碍。
4. 低速循路、遇障停车、检测终点后停车。
5. 记录画面、动作及失败情况。

此阶段不要求通用物体识别或精确距离测量。若仅实现遇障停车，应按“障碍检测与安全停车”验收，不宣称已完成自主绕障。

### 4.2 第二层：路径搜索与实车执行

- 使用预先给定的栅格地图或路口图，明确起点、终点和障碍位置。
- 在仿真中实现 BFS 与 A* 对比；有不同通行代价时可加入 Dijkstra。
- 将规划结果转为分段动作，并通过路口标记等可观测线索确认位置与方向。
- 遇到新增障碍时先停车，确认其在地图中的位置，再更新地图并重新搜索。

**局部避障不等于全局搜索。搜索需要地图或状态空间；路径执行还需要位置和方向信息，不能将摄像头画面直接当作导航地图。**

### 4.3 第三层：可选拓展

- 未知道路探索、路口访问记录与增量地图构建。
- 不同光照、背景和障碍物外观下的鲁棒性测试。
- 引入轻量视觉模型，与规则方法比较准确性和延迟。
- 在仿真中尝试学习型决策，讨论其迁移到实车的困难。

首轮不将 SLAM、强化学习、大模型控制或多车协同列为必做内容。

## 五、初步技术路线

### 5.1 系统架构

优先验证“计算机处理视觉与决策、小车负责采集与执行”的方案，减少对车载算力的依赖。手机端先作为人工遥控入口；能否与程序端同时连接以及如何切换控制权，必须实测确认。

摄像头 → 视频接入 → 图像处理 → 障碍与道路判断 → 决策 → 安全检查 → 控制指令 → 小车运动 → 新画面反馈。

搜索版本额外引入：地图、任务目标、位置与方向估计。人工接管、急停与超时保护应优先于自动控制。

### 5.2 模块设计

| 模块 | 初步实现思路 | 阶段成果 |
| --- | --- | --- |
| 设备接入 | 封装视频与基础运动接口 | 可独立运行的连接、遥控和停止程序 |
| 视觉感知 | 从颜色、边缘和区域分割等简单方法起步 | 道路区域、障碍提示及可视化画面 |
| 状态估计 | 基础版判断道路偏移；搜索版确认位置与方向 | 可供决策使用的小车状态 |
| 环境表示 | 使用给定栅格或路口图，逐步加入障碍更新 | 地图与状态记录 |
| 搜索规划 | 在明确状态空间中实现并比较搜索算法 | 路径、扩展节点数和计算耗时 |
| 行为控制 | 用状态机组织待机、循路、停车、转向和到达 | 可解释的行为切换记录 |
| 安全与日志 | 检查画面过期、通信超时和状态不确定性 | 异常停车记录与实验数据 |

实现语言可优先考虑 Python，视觉处理可考虑 OpenCV；最终工具选择以设备接口和教学环境为准，暂不锁定版本或模型。

### 5.3 安全与能力约束

- 单目画面中的障碍识别不直接代表可靠距离，初期采用低速和经场地实测验证的保守停车条件。
- 画面过期、道路丢失、定位不确定或通信异常时，进入安全停车状态。
- 优先验证设备端的指令超时停车能力；断连后若无法停止，应先补足独立安全措施。
- 在有物理边界的场地测试，远离楼梯、桌边、人群与易损物品，并由现场人员监护。

## 六、实施阶段与验收

具体周数和课时在设备验证、学情确认后安排。

| 阶段 | 主要工作 | 验收或决策依据 |
| --- | --- | --- |
| 1. 交接与可行性验证 | 整理资料，测试视频、控制、停止及断连行为 | 形成接口验证记录；无法接入则先调整设备方案 |
| 2. 遥控与数据采集 | 封装接口，搭建场地，采集典型画面 | 能稳定获取视频并控制、停止小车 |
| 3. 视觉感知基线 | 提取道路，判断障碍，分析误识别 | 固定测试素材上的结果与失败案例 |
| 4. 基础闭环 | 实现低速循路、遇障停车与终点停车 | 多次受控测试记录及人工干预统计 |
| 5. 搜索与执行 | 地图搜索、状态确认与分段执行 | 仿真路径正确，实车能够确认并执行路径 |
| 6. 教学试运行 | 小规模试教，识别难点，调整任务 | 修订后的教案、指导书与评价表 |
| 7. 总结与复用 | 整理代码、数据、作品及教学反馈 | 可复用课程资源包和教改总结 |

## 七、课程组织与评价

### 7.1 教学组织

- 建议每组 3—4 人，分担设备控制、视觉感知、搜索决策及测试记录，并轮换角色。
- 教师提供基础接入框架，学生完成关键算法和实验，避免课时被通信排障占满。
- 设备不足时，先使用录制视频和地图仿真，再分时段进行实车验证。
- 每项实验包含任务说明、输入输出约定、基础任务、提高任务和反思问题。

### 7.2 评价权重建议

| 维度 | 建议权重 | 评价证据 |
| --- | --- | --- |
| 基础功能与安全 | 30% | 接入、循路、停止及异常保护演示 |
| 算法理解与实现 | 25% | 代码、个人解释及算法对比实验 |
| 实验与问题分析 | 25% | 重复测试、失败分析、改进前后对比 |
| 协作与成果表达 | 20% | 分工记录、个人答辩、文档与展示 |

### 7.3 技术指标

- **任务成功率**：固定场地和限时内，无碰撞、无人工接管到达终点的次数 / 总测试次数。
- **安全表现**：碰撞次数、人工接管次数及异常停车情况，分别记录原因。
- **完成时间**：成功运行耗时与失败情况分开汇报，不只展示最快一次。
- **感知效果**：在人工标注的测试素材上统计障碍漏检、误检和道路识别情况。
- **搜索表现**：在相同地图上比较路径长度或代价、扩展节点数及计算耗时。
- **闭环性能**：记录画面延迟、决策更新频率及控制稳定性。

正式考核前统一场地尺寸、速度、障碍布局、重复测试次数与达标阈值。阈值根据试运行结果确定，不预设未经设备验证的精度目标。

## 八、主要风险与应对

| 风险 | 应对措施 |
| --- | --- |
| 设备只支持封闭 App | 优先获取供应商开放资料；无法满足时再评估替换方案 |
| 视频延迟大或控制不稳定 | 降速、短步执行后重新观察、设置超时保护 |
| 光照与背景影响识别 | 先统一场地，再逐步增加变化并收集失败样本 |
| 缺少定位，路径无法执行 | 使用带位置标记的路口图；必要时将搜索与实车局部避障分开验收 |
| 机械误差导致运动偏离 | 缩短开环动作时长，每段运动后通过视觉确认状态 |
| 学生基础差异较大 | 提供基础框架、样例数据和分层任务 |
| 内容过多、进度失控 | 先完成最小闭环，再加入搜索，最后考虑学习型方法 |
